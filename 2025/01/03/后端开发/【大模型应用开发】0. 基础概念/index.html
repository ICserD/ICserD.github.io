一、Token

（一）什么是 token？

在大语言模型中，token 是处理文本的最小离散单位。对模型的输入文本会经过 tokenier 被分割成一个个 token，再进行后续的计算。

具体而言，一个 token 可以是：

  • 一个字
  • 一个词
  • 词的一部份（subword）
  • 标点、空格、特殊符号

（二）为什么需要 token？

主要原因有 2 点，分别如下：

  1. 离散化输入：将无限的文本表达映射到有限的 token 集合

  2. 降低模型理解负担：学习语言的时候，我们并不是一个词一个词的学习的，而是一个 token 一个 token 的学习，使得这些 token 有了上下文语义

    类比我们自己学习语言，“今天天气很好”，我们底层的理解应该是将其分为 3 部分：

    • 今天
    • 天气
    • 很好

    而不是分成 6 个字。这样可以使我们更好地记忆和表达我们的意思。

  3. 统一建模语言：将 token 映射成数字编号（token ID），有利于后续的算法研究和模型训练

（三）什么是 tokenier？

Tokenier 就是将输入文本转化为 token ID 序列的确定性函数。

通常需要做两件事：

  1. 文本切分（分词/子词切分）
  2. 查表得到 token 到 token ID 的映射

（四）token 的重要性

在大模型应用中，token 数量直接决定成本与性能。

大语言模型由大量可训练参数构成，这些参数主要以矩阵形式存在于 Embedding、Transformer 注意力层和前馈网络中。

输入文本经过 Tokenizer 转换为 Token ID 序列后，Token ID 作为索引从 Embedding 矩阵中查表得到对应的向量表示（Embedding）。

Embedding 向量序列经过多层 Transformer 计算，得到每个位置的隐藏状态（Hidden State），随后通过线性映射和 Softmax，输出下一个 Token 的概率分布。

因此大模型的计算本质上就是对 token 对应的 embedding 的计算，token 的数量与推理时间、显存占用、API 计费有直接关系。

二、embedding

（一）什么是 embedding？

在大语言模型中，embedding matrix 是一个可训练的参数矩阵：embedding matrix∈RV×Dembedding \ matrix \in R^{V \times D}embedding matrix∈RV×D，而 embedding 就是这个矩阵中的行向量。

  • V 是词表大小（大小等于 token 表的大小）
  • R 是向量纬度，一个 token 用多大的纬度表示

token ID 我们就可以理解为 embedding 的索引，可以唯一确定一个 embedding 向量（RDR^DRD）。

（二）为什么需要 embedding？

神经网络无法直接处理离散的 Token ID。Token ID 只是一个整数编号，本身不包含任何语义信息，无法表达 Token 之间的相似性或关系。

embedding 的作用是将离散的 token ID 映射到连续的向量空间，使得模型可以进行数值计算并学习语义关系。

（三）embedding lookup 过程

embedding 的使用方式并不是矩阵乘法，而是查表（lookup）：

本质上就是以 token ID 为索引，从 embedding 矩阵中取出对应行向量。

（四）embedding 如何获取语义信息？

embedding 向量在初始化时是随机的，并不包含任何语义。随着模型的训练，不断反向传播更新 embedding 的参数，使得语义相近、上下文相近的 token，其 embedding 在向量空间会逐渐靠近，以此得到 embedding 的语义信息。

由此可见，语义信息其实并不是孤立的，而是在对比中体现的。

（五）embedding 与上下文的关系

embedding 本身是静态的，同一个 token 无论在任何位置，其 embedding 都是相同的。

上下文的相关新并不来自于 embedding，而是来自：

  • transformer 的 self-attention 机制
  • 多层网络对上下文的建模（RNN）

1. token embedding 和 position embedding

由于 transformer 本身不具备序列顺序感知能力，因此需要引入位置信息。

常见的做法是引入一个 position embedding matrix 参数矩阵进行训练。

三、Transformer

（一）什么是 Transformer？

transformer 是一种序列建模的神经网络模型结构，最早应用于自然语言处理任务。其核心特点是通过 attention 机制建模序列中各个位置之间的关系。

在语言模型中，transformer 的输入和输出都是 token 对应的向量序列。

（二）为什么要有 Transformer？

1. 其他序列模型有什么弊端？

在 Transformer 之前，主流的序列模型有 RNN/LSTM、CNN 等，它们都存在一些硬性问题：

  • 无法并行计算，必须按时间步骤/序列顺序计算，推理速度慢
  • 长距离依赖难以建模，远距离的 token 信息会逐步丢失
  • 上下文信息的传递路径过长，第一个词的信息要经过很多步才能影响最后一个词

2. Transformer 解决了什么问题？

Transformer 的设计目标是让序列中任意两个 token 之间都可以通过一跳建立直接联系，这个目标主要通过两个机制解决：位置编码和 attention 机制。

这样带来了几个核心优势：

  • 并行计算，使得大规模训练和推理成为可能
  • 长距离依赖建模能力强，任意两个 token 可以直接建立联系

（三）Transformer 机制原理

1. Transformer 的核心思想

Transformer 的核心是两个重要机制，分别是位置编码以及 Attention 机制。通过位置编码，使得每一个 token 天然自带位置信息，使得并行计算和长距离依赖建模能力跃升；通过 Attention 机制，让每一个 token 的表示融合其他 token 的信息，从而获得上下文语义。

2. Transformer 结构概览

下面的结构图中，红框部分是 Transformer 最核心的部分。

2.1 Input（输入）

对于语言模型，模型的原始输入是 token ID 序列。模型首先通过 embedding lookup，将每个 token ID 映射成一个连续向量，得到 token embedding 序列，一个个 token embedding 组成 embedding 矩阵embeddingtokenembedding_{token}embeddingtoken​。

假设 token 为 LLL 个，一个词向量用 dmodeld_{model}dmodel​ 维度向量表示，那么 embeddingtoken∈RL×dmodelembedding_{token} \in R ^{L \times d_{model}}embeddingtoken​∈RL×dmodel​。

此时的 embedding 只包含 token 的语义信息，不包含位置信息、不包含上下文信息。

2.2 预处理（embedding + position + QKV 投影）

2.2.1 位置编码（position encoding）

由于 transformer 不具备顺序感知能力，需要为每一个 token embedding 注入位置信息：

  • embeddingtokenembedding_{token}embeddingtoken​和embeddingpositionembedding_{position}embeddingposition​是相同维度的
  • 得到的 X∈RL×dmodelX \in R^{L\times d_{model}}X∈RL×dmodel​
    • LLL 表示 token 的个数
    • dmodeld_{model}dmodel​ 表示词向量的维度，也就是 embedding 的维度

X=embeddingtoken+embeddingpositionX = embedding_{token} + embedding_{position} X=embeddingtoken​+embeddingposition​

2.2.2 Q/K/V 先行投影

为了进行注意力计算，引入三组可训练的参数矩阵：WQ,WK,WVW^Q, W^K, W^VWQ,WK,WV，对 embedding 进行线性变换，得到三个经过线性变换的 embedding 矩阵：

Q=X⋅WQK=X⋅WKV=X⋅WVQ = X · W^Q \\ K = X · W^K \\ V = X · W^V \\ Q=X⋅WQK=X⋅WKV=X⋅WV

设计这三个 embedding 的意义：

  • Q：表示当前 token 要查询的信息
  • K：表示每个 token 提供的特征索引
  • V：表示每个 token 的实际信息内容

2.3 多头注意力机制

2.2.1 拆分多个 head

将 Q/K/V 在 embedding 维度上拆分为多个子空间：dmodel=h×dheadd_{model} = h \times d_{head}dmodel​=h×dhead​

对于每一个子空间 headihead_iheadi​，有如下的 embedding：

Q→[Q1,Q2,…,Qh]K→[K1,K2,…,Kh]V→[V1,V2,…,Vh]Q → [Q¹, Q², …, Qʰ] \\ K → [K¹, K², …, Kʰ] \\ V → [V¹, V², …, Vʰ] \\ Q→[Q1,Q2,…,Qh]K→[K1,K2,…,Kh]V→[V1,V2,…,Vh]

2.2.2 对每个 head 的注意力计算

Headi=Attentioni=softmax(Qi⋅KiTdhead)⋅ViHead_i = Attention_i = softmax(\frac{Q_i · K_i^T}{\sqrt{d_{head}}})·V_i Headi​=Attentioni​=softmax(dhead​​Qi​⋅KiT​​)⋅Vi​

该过程完成三件事情：

  • 计算 token 之间的相关性，缩放相关性避免极端值
  • 对相关性进行非线性变换得到注意力权重分布
  • 对信息向量进行加权汇总，得到AttentioniAttention_iAttentioni​
2.2.3 合并多个 head 的结果

将所有的 head 的输出拼接，并通过输出投影矩阵得到融合了多种上下文关系的 embedding 表示！

O=concat(head1,...,headh)⋅WOO = concat(head_1, ..., head_h)·W^O O=concat(head1​,...,headh​)⋅WO

2.4 后处理（Residual + LayerNorm）

将多头注意力的输出与原始输入做残差连接，然后进行归一化处理：

X=LayerNorm(X+O)X = LayerNorm(X + O) X=LayerNorm(X+O)

其作用是：

  • 保留原始信息，避免信息丢失
  • 缓解深层网络的梯度问题
  • 稳定数值分布，提升训练稳定性

2.5 前馈神经网络（FFN）

对每个 token 的 embedding 独立进行非线性变换：

  • σ\sigmaσ 表示的是非线性变换，比如 Relu 等
  • xxx 表示的是某个 token 的 embedding

前馈神经网络（FFN）在语义上是对每个 token 的 embedding 独立作用的非线性变换，但在实现上通过矩阵乘法一次性对整个 embedding 矩阵进行计算。由于 FFN 的参数在所有 token 之间共享，且不涉及 token 之间的交互，因此矩阵计算在数学上等价于逐 token 的独立计算。

FFN(x)=W2⋅σ(W1⋅x+b1)+b2FFN(x) = W_2·\sigma(W_1·x + b_1) + b_2 FFN(x)=W2​⋅σ(W1​⋅x+b1​)+b2​

FNN 通常作用是对已经融合上下文的信息进行非线性语义加工和特征变换，提升模型的表达能力。

（四）Transformer 的训练与预测机制

1. Transformer 的目标

Transformer 训练的目标本质上是在给定上下文的条件下，最大化正确 token 的预测概率。

2. Transformer 的两种使用场景

2.1 Encoder-Decoder（如翻译、摘要）

  • 输入：源序列
  • 输出：目标序列
  • Encoder：负责理解输入
  • Decoder：负责预测生成输出

2.2 Decoder-only（GPT）

  • 输入：同一序列的前缀
  • 输出：下一个 token
  • 只有 Decoder、没有 Encoder

一个 Decoder Block 包括三步：

  1. 掩码自注意力编码
  2. 交叉注意力编码
  3. FNN + Residual + LayerNorm

Masked Self-Attention（只看已经生成的部分）

  • Q/K/V 都来自 Decoder
  • 使用因果掩码，防止看到未生成的 token

Cross-Attention（引入 Encoder 信息）

  • Q 来自 Decoder

  • K/V 来自 Encoder 最后输出的隐藏层 HencH_{enc}Henc​，让 Decoder 在生成时“查询”源语言语义

    如何基于 HencH_{enc}Henc​ 得到 Decoder 需要的 K/V？

    • Q=Henc⋅WQQ = H_{enc} · W^{Q}Q=Henc​⋅WQ 得到 Q，语义是我现在生成到这个状态，我想查什么信息？
    • K=Henc⋅WKK = H_{enc} · W^{K}K=Henc​⋅WK 得到 K，语义是我把 Encoder 的每个 token 转换成一个可被匹配的索引向量
    • V=Henc⋅WVV = H_{enc} · W^{V}V=Henc​⋅WV 得到 V，语义是如果 Decoder 关注这个 Encoder token，能够拿到什么内容

FNN + Residual + LayerNorm

  • 对当前 token 的表示进行非线性变换
  • 不涉及 token 的交互

4. Encoder-Decoder Transformer 推理过程

模型训练完成后，得到训练模型参数，以及固有的模型结构，基于此进行推理。

4.1 Encoder 计算隐藏层

将输入的 token 的 embedding 序列输入到 Encoder，最后得到隐藏层 Henc∈RLsrc×dmodelH_{enc} \in R^{L_{src} \times d_{model}}Henc​∈RLsrc​×dmodel​。

后面 Decoder 可以基于这个隐藏层计算出 K/V 向量，由此得到可以检索的语义向量表示。

这个隐藏层只用算一次，因为模型已经训练好了，参数是固定的，相同的 token 序列输出的隐藏层都是一样的。

4.2 Decoder 自回归生成

流程：从 （开始标志）开始，预测下一个 token，得到下一个 token 之后将下一个 token 纳入到已预测 token 序列，再去预测下一个，直到预测到 结束标志或者达到最大长度限制为止。

每一步自回归做了什么？

  • Masked Self-Attention：使用已经预测的 token 序列计算得到自回归的隐藏层

  • Cross-Attention：使用 Encoder 计算得到的隐藏层得到 K/V，使用 Masked Self-Attention 得到的隐藏层得到 Q，再次计算得到新的隐藏层

    Decoder 是如何基于 Encoder 的隐藏层得到 K/V 的？

    • Decoder 有自己的WQ,WK,WVW^Q, W^K, W^VWQ,WK,WV参数矩阵，在预测过程中，已经是训练好的
    • 用 Encoder 的隐藏层 Henc⋅WKH_{enc} · W^KHenc​⋅WK 得到的 K，语义是把 Encoder 的每个 token 转换成‘可被匹配的索引向量‘

  • 对新的隐藏层进行残差连接、归一化，最后线性映射到词表，最后 softmax 得到概率最大的 token

5. GPT 的预测

  • 只有 Masked Self-Attention
  • Q = K = V = 自身 hidden states
  • 逐 token 自回归生成

四、Prompt Engineering

（一）什么是提示词？

提示词是引导大模型进行内容生成的文本命令。

有了前面 Transformer 的理论基础，我们可以提示词的本质是提供上下文，使得模型的注意力参数在更加具体的空间搜索得到更加符合语义的 token

（二）提示词工程

提示词工程是有技巧地使用提示词，从而最大限度地提高大模型响应的有效性、准确性和实用性。这时一个持续的、不断优化的过程。

Open AI 分享了优化提示词的六大策略：

  1. Write clear instructions 编写清晰的说明
  2. Provide reference text 提供参考文本
  3. Split complex tasks into simpler subtasks 将复杂任务拆分更简单的子任务
  4. Give the model time to “think” 给模型时间“思考”
  5. Use external tools 使用外部工具
  6. Test changes systematically 系统地测试变化
