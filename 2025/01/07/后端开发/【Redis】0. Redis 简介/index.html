【Redis】0. Redis 简介

发表于2025-01-07|更新于2025-01-07|后端开发后端组件数据库组件
|字数总计:679|阅读时长:2分钟|阅读量:

一、Redis 是什么？

Redis，Remote Directory Server 是一个**==基于内存==的高性能 key-value 数据库**，支持多种数据结构，常用于缓存、计数、分布式锁、消息队列等场景。

二、Redis 为什么出现？

最初，Redis 是为了解决传统数据库在高并发场景下的“访问慢、压力大”的问题。

（一）Redis 未出现的场景

2008 年前后，互联网流量爆发式增长。当时主流的数据持久化方案是 MySQL/PostgreSQL，这种方案的缺点很明显，无法承担高并发的访问流量，对一些新的应用场景（点赞、排行榜、实时统计等）明显不适用。

1. 传统数据库的痛点

  1. 读多写少的场景被等同对待：用户信息、商品信息、配置数据这些，每次都要查磁盘，非常浪费

  2. 数据库被迫做不擅长的事情：计数（点赞/收藏）、排行榜、实时统计

    • 关系型数据库的设计目标是：强一致 + 复杂查询，不是简单高频操作！

    针对这种特殊场景，开始分库分表，但分库分表不仅效率低而且复杂度和成本都高

轻量级、高性能的中间层由此诞生 —— Redis！

（二）Redis 的目标

Redis 最初的目标非常清晰，一个极快、简单、能处理大量小数据、能当“数据库前置层”的系统。

从目标我们可以探索一下 Redis 的设计选择。

1. 目标一：极致性能

设计选择

  • 基于内存存储
  • 单线程处理命令
  • IO 多路复用

带来的结果

  • 避免锁
  • 命令模型执行简单
  • 延迟极低，微妙级

2. 目标二：高并发下的稳定性

设计选择

  • 单线程执行命令（逻辑层）
  • 原子操作（INCR，LPUSH）

带来的结果

  • 没有并发安全问题
  • 开发者心智负担低

3. 目标三：节省内存 + 支持多场景

设计选择

  • 多种数据结构
  • 多种编码类型

带来的结果

  • 小数据用紧凑模型
  • 大数据用高效结构

4. 目标四：不取代数据库，而是“辅助”

设计选择

  • 弱化事务能力
  • 不支持复杂 join
  • 提供持久化但不追求强一致性

带来的结果

  • 是传统 SQL 数据库的好搭档

二、Redis 有什么特点？

  • 高性能：数据存储在内存，都是键值对数据，读写性能非常高
  • 高可用：有持久化机制（RDB、AOF）等，支持重启后数据恢复
  • 数据结构丰富，支持 String、List、Hash、Set、ZSet 等多种对象

三、Redis 常见的应用场景

  • 缓存
  • 分布式锁
  • 消息队列
