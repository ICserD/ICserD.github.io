分布式理论基础

本文重点介绍分布式中的基础理论 CAP，以及更具备工程实践意义的 BASE 理论。

一、CAP 理论

1. 背景

分布式理论发展早期，工程师进行分布式系统设计缺乏方向性指导，导致分布式系统设计混乱，缺乏原则。

研究者们一直在探索指导分布式系统设计的原则，于是经过多年努力，CAP 理论诞生。

最早由 Eric Brewer 在 2000 年提出，最初是 CAP 猜想，而后在 2002 年被 Seth Gilbert 和 Nancy Lynch 通过理论证明，使得 CAP 理论正式确立，成为分布式系统设计中的重要理论基础之一。

2. CAP 理论

CAP 理论是一套指导分布式系统设计的原则，该理论指出，在一个分布式系统中，一致性（consistency）、可用性（availablility）、分区容错性（partition tolerance）这三个目标无法同时满足，最多只能满足其中两个。

下面对这三个性质分别作出定义：

  • 一致性/数据一致性：在分布式系统中的所有节点，在同一时间点上拥有相同的数据副本，比如某个节点上的数据更新了，其他节点的数据也要立即更新，读请求无论读哪一个节点都能读到这个最新值

  • 可用性：对于每一个请求，正常节点要在合理的时间内给出正确的响应，则视为提供可用的服务

    这个“合理的时间”是根据系统设计而定，比如系统设计时要求响应时间在 500ms 内，那系统可用就是说所有节点如果收到请求就要在这个时间内响应，并且要给出正确的响应

  • 分区容错性：分区容错性是指分布式系统在网络分区发生时（某些节点间的网络通信异常等情况），仍然能以某种可控的方式继续运行，对外提供可用的服务

3. AP 还是 CP？

CAP 理论看似是从一致性、可用性和分区一致性作出三选二的抉择，但实际上分区容错性是分布式系统必须要选择的。如果不选择分区容错性，意味着分布式系统一旦发生网络分区就不可用，这是不能接受的。

因此在 CAP 理论下，我们的分布式系统设计要根据业务特点考虑来选择 AP 还是 CP。

  • CP：适用于一致性优先的场景，典型场景有金融、分布式数据等

  • AP：适用于可用性优先的场景，大多数是面向 C 端，用户体验要求高的场景

4. CAP 理论局限性

CAP 理论最大的局限性在于强调 C 和 A 的强取舍，在实际应用中 C 和 A 并不往往是简单的二选一的关系，在分布式系统设计中，我们可以进行 C 和 A 的一些折中，而不是一刀切地二选一。

二、BASE 理论

BASE 理论是对 CAP 理论的进一步扩展，强调 C 和 A 并不是完全不可兼得，而是对 C 和 A 进行权衡，更加具有工程实践意义。

BASE 的全称是 “Basically Available, Soft State, Eventually consistency”，强调基本可用、软状态和最终一致性，是分布式系统的工程化设计原则。

  • 基本可用：分布式系统在部分故障的时候，仍然能够提供降级后的服务；比如响应时间变慢、部分功能不可用等
  • 软状态：允许分布式系统在一段时间内不稳定、不一致
  • 最终一致性：只要不要有新的更新，系统最终可以收敛到一致的状态；比如通过定期校对、重试补偿、异步同步等机制实现

BASE 理论是 CAP 理论的工程化演进，给了分布式系统更大的容错空间，可以理解为满足分区容错、基本可用、最终一致。
