【Java 语言】0. Java 语言基础

发表于2025-02-09|更新于2025-02-09|后端开发编程语言
|字数总计:2.1k|阅读时长:6分钟|阅读量:

本文整理一些 Java 基础中自己觉得值得回顾的一些问题。

一、面向对象特性

1. Java 语言有什么特点？如何实现跨平台？

  • Java 是面向对象的程序设计语言，有封装、继承、多态的特点，使得 Java 的代码可维护性和扩展性比较好
  • Java 是跨平台的，是编译解释型语言，基于 JVM 屏蔽机器细节，使得其具有跨平台特性

2. 面向过程和面向对象的区别？

  • 这是两种不同的编程思维
  • 面向过程是把问题拆解成一个个方法来处理
  • 面向对象是把粉体拆解，并设计一个个可以解决问题的对象来解决
  • 一般来说面向对象的编程思维在编写大型项目时比较有优势，代码维护性和可扩展性都比较好

3. 多态是如何实现的？底层原理是什么？

  • 多态是指同一个方法调用，在不同的对象上有不同的行为
  • 多态的本质是 Java 的动态绑定机制，通过对象的 KClass 指针找到方法区的类元数据，在方法区维护类的虚方法表以及接口方法表，通过方法表定位到具体的方法入口
  • 虚方法表是为每个类维护的方法表，非 private, 非 final, 非 static 的方法都是虚方法，可以被重写。子类继承父类的虚方法表，如果重写了方法则替换对应方法的入口地址、如果新增方法则在虚方法表后追加新方法的入口地址
  • 接口方法表是每个类维护其实现的接口的方法表

二、语言特性

1. 方法重写和方法重载是什么？有什么区别？

  • 方法重载是同一个类中，同一个方法名，但方法参数、返回值可能不同
  • 方法重写是子类可以重写父类的方法，方法名、方法参数必须相同，返回值可以是原来返回值的子类

2. 接口和抽象类的区别？

相同点：

  • 都不能被实例化
  • 都可以有抽象方法和默认实现

不同点：

  • 抽象类只支持单继承、接口支持多继承
  • 抽象类可以维护对象级的成员变量，接口只能放常量，无法维护状态
  • 语义上，接口是用于定义能力的，用于扩展类的功能，是无状态的；抽象类是用于定义模板的，定义行为和组织形式，并且可以有状态

3. 深拷贝、浅拷贝、引用拷贝是什么？

  • 引用拷贝本质上是对象引用的赋值，不会创建新对象，多个变量指向同一个堆对象
  • 浅拷贝会创建新对象，基本类型变量会进行拷贝，但是引用类型变量依旧是引用拷贝，Object.clone() 就是浅拷贝
  • 深拷贝会创建新对象，基本类型变量会进行拷贝，引用类型变量会新建对象再进行拷贝，拷贝后的对象与原对象完全独立

4. Java 中是值传递还是引用传递？还是两者共存？

  • 在 Java 中，只有值传递
  • 引用传递本质也是一种值传递，只不过传递的是引用地址而已

三、常见类：Object、String

1. Object 类有哪些常见的方法？

  • 与本类有关的方法：getClass, hashCode, toString
  • 与其他类有关的方法：clone, equals
  • 与线程安全有关的方法：wait, notify, notifyAll

2. 重写 equals 方法时为什么一定也要重写 hashCode 方法？

  • 在 Java 中，HashMap 这一类的底层实现是基于 hashCode + equals 来实现比较的
  • 要满足如下语义：hashCode 不相等的两个对象一定不相等，equals 的两个对象代表两个对象相等，此时 hashCode 也一定相等
  • 如果重写 equals 方法没有重写 hashCode 方法，可能会破坏上面的语义，导致 HashMap、HashSet 这类容器使用时发生超出预测的错误，也就是可能出现 equals 相等但是 hashCode 不相等的情况，那就会出现重复元素放在不同的桶中
  • 在实际工作中，如果某个类要作为 Map 的 key，或者是可能会参与去重的场景，需要考虑一下是否要重写 equals 和 hashCode，我一般很少碰见，碰见了可以用 Lombok 注解自动生成，具体原理还没去细究过

3. String, StringBuilder, StringBuffer 的区别？

  • String 是不可变类，一旦创建不可修改
  • StringBuilder 和 StringBuffer 都是 AbstractStringBuilder 的实现类，提供了许多操作字符串的方法，内部也是通过 char 数组来存储字符串，但是是可变的
  • StringBuilder 和 StringBuffer 的主要区别是 StringBuffer 是线程安全的，对字符串操作加了锁，而 StringBuilder 是非线程安全的

4. 常量池、运行时常量池、字符串常量池分别是什么？

  • 常量池是 Java 类编译后的字节码中的 Constrant Pool 部分，存储的是对 Java 代码编译后的各种字面量和符号引用
  • 运行时常量池是 JVM 启动后，将类的字节码加载进内存，常量池进入方法区变成运行时常量池，会随着 JVM 的运行，比如新加载类等操作，运行时常量池会发生变化
  • 字符串常量池是用于存储字符串常量的，本质上是一张哈希表，JDK 7 后分布在堆区，主要用于避免字符串冗余存储，放在堆区也有利于通过垃圾回收机制优化字符串的存储

5. String s1 = new String(“111”) 创建了几个对象

  • 两个对象，字面量 “111”，会优先检查字符串常量池是否有字符串的引用，如果没有则在堆区新建一个字符串对象，将其引用放在字符串常量池
  • new 关键字会在堆区创建一个字符串对象，然后字符串对象内部的字符数组指向 “111” 内部的字符数组

6. intern() 方法的作用？

  • intern() 方法用于将字符串放入字符串常量池进行管理，减少重复字符串的创建
  • 比如 String b = a.intern()，a.intern() 首先会看看字符串常量池有没有字符串 a 的引用，有的话直接返回，没有的话将对象 a 的引用放到字符串常量池，再返回其引用

四、Java 异常体系

1. 介绍一下 Java 的异常体系

  • 在 Java 中 Throwable 接口是异常体系的顶级父接口
  • 异常分为两大类，Error 和 Exception，其中 Error 是系统无法处理的异常，一般也称为错误、Exception 是系统可以捕获处理的异常
  • Exception 分为运行时异常和编译期异常，RuntimeException 及其子类都是运行时异常，其他子类都是编译期异常，需要被捕获或声明处理

五、反射

梳理反射 API 体系

理解反射背后的原理，从 JVM 角度

1. 什么是反射？

  • 反射是将 Java 对象的各个组成部分比如成员变量、成员方法等映射成对象，在运行时提供给程序访问的机制
  • 反射的优点是提供了操作对象元数据的途径，缺点是破坏了封装性

六、代理技术

  • 静态代理
  • 动态代理：JDK 动态代理、CGLIB 动态代理及其原理

1. 什么是动态代理？

  • 代理技术是不直接使用目标类，而是通过代理类来使用目标类，并可以在代理类对目标类的方法进行功能扩展的过程
  • 动态代理就是动态生成代理对象的技术，分为 JDK 动态代理和 CGLIB 动态代理
    • JDK 动态代理是基于接口生成代理对象的，因此目标类必须是实现某接口，而且也只能扩展和代理接口方法
    • CGLIB 动态代理不需要目标类必须实现接口，通过生成目标类的子类来作为代理对象，但是注意，对于 final, private, static 修饰的方法无法代理
